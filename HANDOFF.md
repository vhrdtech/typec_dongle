## Decided (conservative calls made without asking, per the night-run instructions)

- **deb/rpm tool: `cargo-deb` + `cargo-generate-rpm`**, not nfpm. Both are plain `cargo install`,
  consistent with how this repo already handles `cargo-bloat` / `cnt_cli` in `just fw-size`; nfpm
  needs a Go toolchain, a real downside with no offsetting gain for just two formats. The existing
  design doc (`docs/design/packaging/index.md`) floats nfpm only as a "long run, broader range of
  formats" tip, not a requirement. Both tools confirmed (web search) to support glob assets, needed
  for the man page tree.
- **Man pages via a new `xtask` workspace crate** (`cargo run -p xtask --release -- target/dist/man`),
  using `clap_mangen::generate_to(donguru_cli::cli::Cli::command(), out_dir)` — confirmed this walks
  the whole subcommand tree recursively, one `.1` file per command. Matches the task's explicit
  "xtask or build step, not a shell program" instruction.
- **Completions are not regenerated by a new tool**: the CLI can already print them
  (`donguru completions <shell> --bin <name>`, `src/commands/completions.rs`). Packaging just calls
  the freshly built binary for `{bash,zsh,fish} x {donguru,dg}` (6 files) and ships the output as
  package assets in the system-wide completion dirs (`/usr/share/bash-completion/completions/`,
  `/usr/share/zsh/site-functions/_NAME`, `/usr/share/fish/vendor_completions.d/NAME.fish`) — NOT the
  per-user XDG dirs `donguru completions --install` writes to (that command is for `just install` on
  a dev machine, not for a system package running postinst as root with no real end-user HOME).
- **`dg` is a symlink to `donguru`**, created by postinst/postrm (`ln -sf donguru /usr/bin/dg` on
  install, `rm -f` on remove/purge) since cargo-deb/cargo-generate-rpm assets are real file copies,
  not symlinks. Same postinst/postrm also run `udevadm control --reload-rules && udevadm trigger`
  (both `|| true`) so an already-plugged dongle doesn't need a replug after install.
- **udev rule is a static package-owned file** (`packaging/60-donguru.rules`, `SUBSYSTEM=="usb"` match
  on `donguru_core::device::{USB_VID,USB_PID}` = `c0de:cafe`, `TAG+="uaccess"`), installed to
  `/usr/lib/udev/rules.d/`, independent of the live `donguru udev generate/install/uninstall/status`
  CLI command. Important: **CLI-8 (`udev generate/install/uninstall/status`) is entirely stubbed
  today** (`donguru-cli/src/commands/udev.rs`, every arm calls `super::stub(...)`) despite
  FEATURES.md's CLI-8 note claiming `generate` already writes the rule — that note is stale. CLI-8 is
  assigned to the parallel `cli-plumbing` session tonight; do not touch `udev.rs`. The static package
  rule sidesteps the stub entirely, which is the right call regardless of when CLI-8 lands: real
  distro packages conventionally ship a vendor rule file, they don't shell out to the installed binary
  at package-build time.
- **License: "TBD"**, per the user's explicit instruction and PKG-4. Needs `license.workspace = true`
  added to `donguru-cli/Cargo.toml` (currently no `license` field at all on that crate, so neither
  packaging tool can read it even though the workspace sets `license = "TBD"`). A one-line placeholder
  `LICENSE` file at repo root (plain text: "TBD — see PKG-4") is needed too, so cargo-deb's
  `license-file` can point at real content instead of trying to match "TBD" against its bundled SPDX
  license database (which would fail the build). Publishing stays out of scope — CI only builds and
  uploads artifacts, no `.deb`/`.rpm` upload to any repository.
- Man pages ship **uncompressed** (no `.gz`) for this first cut — `man` works fine either way, only
  `lintian` would note it. Keeps the xtask and justfile recipe simpler; worth revisiting later but not
  a blocker.
- `dg` gets one small hand-written stub man page (`packaging/dg.1`, "see donguru(1)") rather than a
  full duplicate tree under the `dg-*` name — avoids doubling ~60-100 generated files for an alias.

## Gotchas found during research (don't re-derive)

- `cargo-deb` builds the project itself by default; pass `--no-build` once we've already built in
  step 6, to avoid compiling twice.
- `cargo-generate-rpm` never builds — always run `cargo build --release` first.
- Asset `source` paths: cargo-deb replaces a `target/release/...` prefix with the real target dir
  itself (handles workspaces/cross-compilation), so just write it literally that way. cargo-generate-rpm
  with `-p donguru-cli` tries the source path relative to the **current directory first**, then
  relative to the package directory — run both tools from the workspace root (not `cd`'d into
  `donguru-cli/`) so `target/dist/...` and `packaging/...` paths resolve the same way for both.
- `donguru_core::device::USB_VID` / `USB_PID` = `0xc0de` / `0xcafe` (`donguru-core/src/device.rs`) —
  use these in the udev rule, don't hand-type hex that could drift from the real descriptor.
- FEATURES.md CLI-8 note is stale (claims `generate` works; code is 100% stub). Don't rely on it,
  don't fix it here — that's `cli-plumbing`'s session tonight.
